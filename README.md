# Server Control Web

Модульная панель управления сервером через браузер. Работает на **Windows 11** и **Ubuntu** (и других Linux), написана на чистом Python — **без внешних зависимостей**, ничего ставить через pip не нужно. Интерфейс сделан в стиле GitHub (Primer, настоящие иконки Octicons, светлая и тёмная темы).

## Возможности

- **Вход по логину и паролю**, роли «администратор» / «просмотр», защита от подбора пароля, CSRF-защита, пароли хранятся как PBKDF2-хэши.
- **Первичная настройка прямо в браузере** при первом запуске (код установки печатается в консоль — захватить непонастроенный сервер посторонний не сможет).
- **Тип установки** задаётся в `config.json` (`"type"`) или в мастере:
  - `panel` — «Хостинг и нода управления»: хостит веб-панель, управляет собой и другими нодами;
  - `node` — «Нода»: подчинённый сервер, которым управляют из панели по токену.
- **Ноды**: подключили ноду по адресу и токену — выбрали её в шапке, и терминал, файлы, службы и все остальные модули работают на ней.
- **Автообновление через GitHub Releases** по тегу (точный тег, маска или «плавающий» тег вроде `stable`), проверка SHA-256, резервная копия и откат.
- **Модули с полным доступом**: модуль может добавлять страницы и API, перехватывать любые запросы, менять HTML/ответы сайта, подменять функции ядра и выполнять команды в системе. См. [docs/MODULES.md](docs/MODULES.md).
- Встроенные модули: **Обзор** (CPU/RAM/диски), **Терминал**, **Файлы** (менеджер + редактор), **Службы** (systemd / службы Windows), **Ноды**, **Пример модуля** (шаблон).

## Быстрый старт

Нужен только **Python 3.8+**.

### Ubuntu / Debian

```bash
sudo apt install -y python3
git clone https://github.com/Kikimorza/Server-Control-Web.git
cd Server-Control-Web
./run.sh                          # просто запустить
# или как службу systemd (автозапуск, автоперезапуск при обновлении):
sudo ./deploy/install-linux.sh
```

### Windows 11

```powershell
winget install Python.Python.3.12
git clone https://github.com/Kikimorza/Server-Control-Web.git
cd Server-Control-Web
.\run.bat                         # просто запустить
# или как автозапускаемую задачу (PowerShell от администратора):
powershell -ExecutionPolicy Bypass -File deploy\install-windows.ps1
```

Без git: скачайте `server-control-web.zip` из [Releases](https://github.com/Kikimorza/Server-Control-Web/releases), распакуйте и запустите `run.sh` / `run.bat`.

### Первая настройка

1. Откройте `http://<адрес сервера>:8080`.
2. Введите **код установки** — он выведен в консоль при запуске и лежит в `data/setup_token.txt`.
3. Выберите тип (если он не задан в `config.json`), создайте администратора, при желании настройте обновления.
4. Для типа `node` в конце будет показан **токен доступа** — он нужен, чтобы подключить ноду к панели (показывается один раз; новый можно создать в *Настройки → Доступ ноды*).

> По умолчанию панель слушает HTTP на `0.0.0.0:8080`. Пароль по открытому HTTP передаётся без шифрования: включите TLS (`tls.cert` / `tls.key` в `config.json`) или поставьте перед панелью reverse proxy (nginx, Caddy) и включите `trust_proxy`. Чтобы сначала настроить всё локально, запустите с `--host 127.0.0.1`.

## Конфигурация (`config.json`)

Файл необязателен: все значения имеют умолчания, пример — [config.example.json](config.example.json). Большинство настроек меняется в интерфейсе (*Настройки*).

| Поле | По умолчанию | Описание |
|---|---|---|
| `type` | не задан | `"panel"` — хостинг и нода управления, `"node"` — просто нода. Если задан, мастер этот шаг пропускает. |
| `name` | имя компьютера | Название сервера в шапке и списке нод. |
| `host`, `port` | `0.0.0.0`, `8080` | Адрес и порт. Также `--host`, `--port` в командной строке. |
| `tls.cert`, `tls.key` | пусто | Пути к сертификату и ключу — включают HTTPS. |
| `session_hours` | `12` | Время жизни сессии. |
| `trust_proxy` | `false` | Брать IP клиента из `X-Forwarded-For` (только за своим reverse proxy). |
| `update.*` | см. ниже | Параметры автообновления. |

Аргументы запуска: `--config <файл>`, `--data <каталог>`, `--type panel|node`, `--host`, `--port`, `--rollback`, `--version`. Переменные окружения: `SCC_CONFIG`, `SCC_DATA`.

Данные (пользователи, сессии, настройки модулей, резервные копии обновлений, логи) лежат в `data/`.

## Ноды

1. На втором сервере установите панель, в мастере выберите **Нода**, сохраните токен.
2. В главной панели: **Ноды → Добавить ноду** — укажите адрес (`https://host:8080`), токен. Если у ноды самоподписанный сертификат, отметьте «Не проверять TLS-сертификат».
3. В шапке рядом с названием появится переключатель нод. Выбрав ноду, вы работаете с её файлами, терминалом, службами — через прокси панели. Токен хранится только на панели (`data/modules/nodes.json`, права 0600), на ноде — лишь его SHA-256.

Прокси доступен только администраторам. Любой установленный на ноде модуль автоматически доступен из панели, отдельный код для удалённого режима не нужен.

## Автообновление (GitHub Releases)

Панель периодически смотрит релизы репозитория `update.repo` (по умолчанию `Kikimorza/Server-Control-Web`), выбирает подходящий **по тегу**, скачивает прикреплённый zip, проверяет SHA-256, делает резервную копию, заменяет файлы и перезапускается. Настройки, `data/`, `config.json`, ваши модули и лаунчеры `run.sh`/`run.bat` не затрагиваются.

| Параметр `update.*` | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | Проверять обновления по расписанию. |
| `tag` | `v*` | **Точный тег** (`stable`, `v1.2.0`) или **маска** (`v*`, `v1.*`). Из подходящих берётся самый новый. |
| `asset` | `server-control-web*.zip` | Маска имени zip-файла в релизе. Если такого файла нет, берётся архив исходников тега. |
| `check_interval_hours` | `6` | Интервал проверки. |
| `auto_apply` | `false` | Ставить без подтверждения (не рекомендуется). |
| `allow_prerelease` | `false` | Учитывать pre-release. |
| `require_checksum` | `false` | Отклонять релизы без SHA-256 (`digest` у файла или `*.sha256` рядом). |
| `repo`, `token` | — | Репозиторий и (необязательно) GitHub-токен для приватных репозиториев. |

Как сравниваются версии: если теги числовые (`v1.2.3`) — обновление предлагается, когда версия тега выше установленной. Для нечисловых («плавающих») тегов вроде `stable` панель запоминает метку файла и предлагает обновление, когда релиз пересобран.

### Как выпустить релиз

Обычный релиз — через тег (версия берётся из него):

```bash
git tag v1.1.0 && git push origin v1.1.0
```

Workflow [.github/workflows/release.yml](.github/workflows/release.yml) прогонит тесты, соберёт `server-control-web.zip` + `.sha256` и опубликует релиз. Для «плавающего» тега: *Actions → Release → Run workflow*, `tag = stable` — релиз пересоздаётся на текущем коммите, а панели с `update.tag = stable` обновятся. Вручную: `python tools/build_release.py --version 1.1.0` → `dist/`.

Откат: `python run.py --rollback` восстанавливает файлы из последней резервной копии (`data/backup/`).

## Модули

Модуль — папка `modules/<id>/` с `module.json`, необязательным `main.py` (серверная часть) и `web/` (интерфейс). Модуль работает внутри процесса панели с её правами и может всё: добавлять страницы и API, перехватывать и менять запросы и ответы, править HTML сайта, подменять код ядра, запускать команды ОС. Всё, что модуль регистрирует через API, автоматически снимается при выключении.

Установка: положить папку в `modules/` или *Настройки → Модули → Установить модуль* (zip). Установленный модуль выключен, пока администратор его не включит. Полное описание и примеры — [docs/MODULES.md](docs/MODULES.md), шаблон — `modules/hello-example`.

> ⚠️ Модуль — это код с полным доступом к серверу. Устанавливайте только то, чему доверяете. Встроенные модули при обновлении заменяются версиями из релиза: свои правки делайте в копии с другим `id`.

## Безопасность — коротко

- Все API требуют сессию; запись — ещё и CSRF-токен; cookie `HttpOnly`, `SameSite=Strict`; строгий CSP.
- 5 неудачных входов → блокировка IP на 5 минут. Смена пароля завершает сессии пользователя.
- Роль «просмотр» не может выполнять команды, читать файлы, менять настройки и работать через прокси на ноды.
- Терминал, файлы и службы работают с правами пользователя, под которым запущена панель (в `deploy/` — root / SYSTEM). Ограничить обзор файлов можно параметром `root` в `data/modules/files.json`.
- Терминал выполняет команды по одной (не интерактивная оболочка), с ограничением по времени.

## Структура

```
run.py / run.sh / run.bat   запуск (+ автоперезапуск после обновления)
scc/                        ядро: сервер, авторизация, модули, обновления, веб-интерфейс (scc/web)
modules/                    встроенные и ваши модули
deploy/                     systemd-служба, установщики для Linux и Windows
tools/                      сборка релиза, генерация иконок
tests/smoke_test.py         сквозная проверка (панель + нода + прокси + права + модули)
docs/MODULES.md             руководство по модулям
```

Проверка работоспособности: `python tests/smoke_test.py`.
